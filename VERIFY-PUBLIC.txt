HOW TO CHECK IT  (five commands; any machine; no network)
  Put the disclosed data in a file called DATA and the two lines in REFERENCE.

  { printf 'SC2-A\n'; cat DATA; } | openssl dgst -sha3-512     # -> S3A
  { printf 'SC2-B\n'; cat DATA; } | openssl dgst -sha3-512     # -> S3B
  openssl dgst -blake2b512 DATA                                # -> B2
  sha512sum DATA              (macOS: shasum -a 512 DATA)      # -> S5

  ALL FOUR must equal the values in line 2. Three or fewer is a FAILURE.

  tr -s '[:space:]' ' ' < REFERENCE | sed 's/^ *//; s/ *$//' | tr -d '\n' \
    | openssl dgst -sha3-512                                   # -> the SHORT FORM

  The fifth ties the reference to what was published: a matching short form
  proves these are THE published lines, not merely some lines. Line breaks, blank
  lines or extra spaces added by a website do not matter: every run of whitespace
  is made one space, and the ends trimmed, before hashing.

  Without openssl (Python standard library; prints S3A, S3B, B2, S5 in that order):
  python3 -c "import hashlib;d=open('DATA','rb').read();print(hashlib.sha3_512(b'SC2-A\n'+d).hexdigest());print(hashlib.sha3_512(b'SC2-B\n'+d).hexdigest());print(hashlib.blake2b(d,digest_size=64).hexdigest());print(hashlib.sha512(d).hexdigest())"

EVIDENCE OF THE DATE  (this is evidence, not mathematical proof)
  1. Timestamp tokens (NAME.tsr, each with its request NAME.tsq). Verify each AT
     ITS OWN STAMPING TIME, against an anchor certificate you obtained yourself
     (EU Trusted List, an OS trust store, or the operator's site, by fingerprint):
       openssl ts -reply -in NAME.tsr -text | grep '^Time stamp'
       openssl ts -verify -in NAME.tsr -queryfile NAME.tsq -CAfile ANCHOR.pem \
               -partial_chain -attime EPOCH
     where EPOCH is that time in seconds since 1970 (date -u -d 'TIME' +%s).
     -partial_chain lets a CA or unit certificate (what trusted lists publish) be
     the anchor. Do not use -no_check_time: it switches validity checks off.
     The CRLs saved in crl/NAME/ show whether the signing key had been revoked:
     find the timestamping certificate's serial number and look for it in them
     (openssl crl -inform DER -in FILE -noout -text); a revocation date before
     the stamping time voids that token. sc2-tsverify.sh does all of this.
  2. The Bitcoin anchor (REFERENCE.ots). It shows the reference's SHA-256 leads
     to the merkle root of one Bitcoin block. sc2-btc.py checks that offline
     against the archived block header; "ots --no-bitcoin verify" prints the
     block height and merkle root to check by hand. Then confirm on any two
     independent explorers or nodes that the block at that height has the
     block hash printed.
  3. Independent archives and the national library copy listed with the
     disclosure (Software Heritage, Internet Archive, BnF depot legal).

WHAT A MATCH PROVES / DOES NOT PROVE
  Proves: DATA is byte for byte what the REFERENCE referred to, and nothing about
    it was learnable from the REFERENCE alone.
  Does not prove: that the answer is true; nor, by itself, the date -- that rests
    on the independent records above.

RECONSTRUCTING DATA FROM A PRINTED MASTER SHEET
  A master sheet is the file in uppercase hexadecimal, 64 characters per line.
  Strip the line numbers and the 4-character checksums, join into one string,
  convert hex to bytes. Each checksum is the first 4 hex characters of SHA3-256
  of "NNN|<the 64 characters>", uppercase, so a mistyped character shows up on
  one line only. Hex uses no O, I, S or G, so 0/O and 1/I cannot be confused.
  paperkit.py, published with the reference, does all of this from a typed or
  OCR'd copy, repairs misreadings such as O for 0, and names any line to re-read:
    python3 paperkit.py --decode SHEET.txt DATA
